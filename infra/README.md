# spn-mock — infrastructure (AWS CDK)

spn-mock runs next to wave-media: one ECS service per stage in the wave cluster, behind wave's ALB, on
`spn-mock.<wave domain>` (covered by wave's wildcard certificate and `*.<domain>` DNS record). Images are built
by a pipeline in the tools account from this repository.

| Stack | Account | Contents |
|---|---|---|
| `spn-mock-pipeline` | tools (100025280990) | ECR repository, CodePipeline: GitHub → build image → deploy to dev |
| `spn-mock-<stage>` | stage | ECS task + service, target group, ALB rules, credentials in Secrets Manager, log group, deployment role |

Accounts, domains and the GitHub connection are in `lib/config.ts`.

## How it is wired

- `/admin*` is protected at the ALB with `authenticate-cognito` against wave's **workforce** user pool (staff
  logins, MFA). `/checkout/*` (end users, iframe) and `/v1/*` (API key) are open, like a real provider.
- State: SQLite on the EC2 host, bind-mounted from `/data/spn-mock-<stage>`. Survives redeploys, not instance
  replacement. The seed is idempotent and re-applies the API key / webhook secret / webhook URL from env on every
  start, so losing the file never changes the credentials wave uses. Deployments are stop-then-start
  (`minHealthyPercent 0`): SQLite must have a single writer.
- Credentials are generated by Secrets Manager: `spn-mock/<stage>/api-key`, `spn-mock/<stage>/webhook-secret`.
  The same values must be set in wave's `wave/<stage>/app` secret as `SPN_API_KEY` / `SPN_WEBHOOK_SECRET`,
  together with `SPN_BASE_URL=https://spn-mock.<domain>`.
- Read from wave-media's infra at deploy time (SSM, stage account): `/wave/<stage>/vpc-id`,
  `/wave/<stage>/alb/https-listener-arn`, `/wave/<stage>/alb/security-group-id`, `/wave/<stage>/ecs/capacity-provider`,
  `/wave/<stage>/cognito/{workforce-pool-arn,alb-auth-client-id,alb-auth-domain}`. wave-media must be deployed first.

## First deployment of a stage

```bash
cd infra && pnpm install
# 1. stage account — service at desiredCount 0 (no image yet)
pnpm exec cdk deploy spn-mock-<stage> -c bootstrap=true --profile <stage profile>
# 2. tools account — once; the first pipeline run builds the image and deploys it (to a 0-sized service)
pnpm exec cdk deploy spn-mock-pipeline --profile <tools profile>
# 3. copy the generated credentials into wave/<stage>/app (see above), restart the wave api
# 4. stage account — scale to 1
pnpm exec cdk deploy spn-mock-<stage> --profile <stage profile>
```

Checks: `GET https://spn-mock.<domain>/health` → 200; `/admin` → redirect to the Cognito login;
`/v1/destinations` with `Authorization: Bearer <api key>` → the seeded destination.

Later: pushes to `main` deploy to dev automatically. The mock runs on dev only (no qa, never prod).
Infrastructure changes are applied with `cdk deploy` from this folder. Add `"qa"` to `PIPELINE.stages` and `manualApprovalBefore`
if QA ever needs the payment step on their environment.
